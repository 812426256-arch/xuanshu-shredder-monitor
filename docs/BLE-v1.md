# BLE 状态协议 v1

适用链路为 STM32H743 → 串口 → ESP32-S3 → BLE → Android。ESP32-S3 是 GATT 服务端，Android 是客户端。本文约定 BLE 部分，串口协议由固件项目决定。蓝牙待实机联调。

## 广播和 GATT

| 项目 | 约定 |
| --- | --- |
| 广播 | 可连接广播或扫描响应应包含下列 128 位服务 UUID。App 按该 UUID 扫描，设备名称可自定义。 |
| 主服务 UUID | `a5836ead-504e-4d53-a845-856260567e5a` |
| 状态特征 UUID | `a5836ead-504e-4d53-a845-856260567e5b` |
| 特征属性 | 推荐同时提供 `READ` 和 `NOTIFY`，并带 CCCD `0x2902`。App 优先订阅，也兼容 `INDICATE`，订阅不可用时每约 1.5 秒读取一次 `READ` 特征。 |
| 数据长度 | 固定 10 字节二进制帧，单条通知或一次读取返回一帧。默认 ATT MTU 23 即可承载。 |
| 写入 | App 写 CCCD 以开启通知或指示。状态特征为只读。 |

## 状态帧

所有整数均为无符号，多字节字段为小端序。

| 偏移 | 字节数 | 字段 | 含义 |
| ---: | ---: | --- | --- |
| 0 | 1 | `version` | 固定为 `0x01`。 |
| 1 | 1 | `straw_type` | `0` 未提供，`1` 小麦秸秆，`2` 水稻秸秆，`3` 玉米秸秆。 |
| 2 | 1 | `gear` | `0` 未提供，`1` 低档，`2` 中档，`3` 高档。 |
| 3 | 1 | `run_state` | `0` 待机，`1` 运行中，`2` 已完成，`3` 故障，`4` 未提供。 |
| 4–7 | 4 | `remaining_s` | H743 上报的整数秒。有效值 `0`–`359999`，`0` 显示 `00:00`，`0xFFFFFFFF` 表示未提供，显示 `--:--`。 |
| 8–9 | 2 | `sequence` | 每生成一条有效状态快照加 1，`65535` 之后回绕到 `0`。 |

示例 `01 03 02 01 4B 00 00 00 34 12` 表示玉米秸秆、中档、运行中、75 秒、序号 `0x1234`。界面显示 `01:15`。

示例 `01 00 00 00 FF FF FF FF 35 12` 表示待机、秸秆和档位未提供、剩余时间未提供、序号 `0x1235`。界面显示 `--:--`。

## 上报和有效期

1. ESP32-S3 应在正常接收 H743 状态时约每秒生成并发布一帧。状态值相同也应推进序号，以支持待机、故障和完成时的状态监测。`READ` 应提供最新有效帧。H743 状态源超时时，ESP32-S3 停止状态通知，读取应返回空值或 ATT 错误，避免刚连接的手机收到已过期的缓存。
2. App 丢弃长度、版本、枚举或时间范围非法的帧。以 16 位模数计算前进量，范围 `1`–`32767` 视为新帧。重复帧不刷新有效期。旧序帧在当前数据未过期时丢弃，过期后允许序号已变化的帧恢复显示，以支持设备序号重置。
3. GATT 初始化成功后，等待第一条有效帧满 5 秒，或距离上次接收新帧满 5 秒，连接状态显示「数据未更新」。时间回到 `--:--`，其余作业字段清空。新有效帧到达后恢复显示。App 用本机单调时钟判定数据有效期。
4. 系统报告链路断开、用户主动断开或 GATT 初始化失败时，显示「已断开」并清除状态。回到蓝牙模式后可以重新扫描、连接。进入后台会释放链路。
5. 蓝牙模式直接展示最后一帧有效快照中的时间。待机、完成、故障等状态都使用设备给出的时间字段。
